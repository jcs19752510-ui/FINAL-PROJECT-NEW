# 테스트 결과서 (Test Result Report) — unit-36

## 1. 개요
- 테스트 대상: STT 실시간 스트리밍 미리보기(`POST /interviews/{id}/turns/preview`,
  프런트 `runPreviewCycle`/`startPreviewLoop`/`stopPreviewLoop`)
- 테스트 유형: 단위+통합 병합(Low 등급, 신규 기능 3개 작업 단위 이하)
- 적용 Tier: Low(기존 최종 제출 경로에 배선 변경 없음, 완전히 새로운 병렬 경로)
- 적용 속도 트랙: L2(백엔드는 실제 HTTP E2E로 정식 검증, 프런트는 브라우저
  수동 확인이 부분적으로 남아 L3에는 못 미침)
- 테스트 목적: 신규 엔드포인트의 동의/레이트리밋/STT 호출/응답 형식이 실제로
  동작하는지, 기존 최종 제출 경로에 회귀가 없는지 실측 확인
- 관련 산출물: `docs/harness/units/unit-36-note.md`, `docs/harness/decisions.md`
  DEC-052
- 테스트 수행자(에이전트): 본 세션
- 테스트 일시: 2026-09-23

## 2. 테스트 범위 및 제외 범위
- 범위: 백엔드 신규 엔드포인트 실제 HTTP E2E(격리 인스턴스, 실제 합성 음성
  포함), 기존 `/turns` 회귀 확인, 프런트 TypeScript 컴파일/린트, 실제 브라우저
  로그인·회원가입·면접 생성 흐름
- 제외 범위 및 사유: (1) 실제 마이크로 "미리보기 텍스트가 화면에 누적
  표시"되는 것의 육안 확인 — 사전고지 동의 화면의 기존 스크롤 게이트(이
  유닛과 무관)를 자동화로 통과하지 못해 면접장 화면 진입 전에 중단됨.
  (2) 라이브 개발 백엔드(8010)에서의 실사용 확인 — 그 프로세스가 이번 세션
  코드를 아직 반영하지 않은 상태라(재시작 필요) 격리 인스턴스(8503)로 대체.
  (3) Safari/Firefox 등 비-Chromium 브라우저 호환성.

## 3. 테스트 환경
- Windows, Python 3.13(`backend/.venv`), PostgreSQL(5544, 라이브 개발 DB —
  격리 테스트 계정만 사용 후 즉시 삭제), Redis(레이트리밋 카운터), 신규
  격리 uvicorn(포트 8503), 실제 Piper TTS로 합성한 한국어 음성
- 테스트 데이터: `unit36-*@example.com` 계정 5개, `unit36c-*@example.com`
  계정 1개, `browsertest-stt@example.com`(브라우저 수동 확인용) 1개 — 전량
  테스트 후 삭제
- 전제 조건: 라이브 Celery 워커가 이미 떠 있어(사용자 개발 환경) 테스트
  중 생성한 면접의 `opening_question` job이 실제로 처리됨(부수 효과,
  결함 아님 — teardown에서 함께 정리)

## 5. 커버리지
- 백엔드 신규 로직(엔드포인트 핸들러 전체 분기: 성공/빈오디오/타인소유/회귀)
  전량 실제 HTTP 실행으로 커버. 레이트리밋 초과(429) 분기 자체는 20회를
  실제로 채우지 않아 미실행(상한 로직은 기존 `check_and_increment_turn_rate_limit`
  검증 완료 함수와 완전히 동일한 패턴 재사용이라 위험 낮음, unit-27-test.md
  TC-008/009 선례로 갈음).
- 프런트 신규 로직(`runPreviewCycle` 등)은 컴파일/린트만 커버 — 실제 브라우저
  런타임 동작(다중 MediaRecorder 순차 생성)은 TC-010 보류로 미검증.

  기존 프로세스 이상 1건**을 발견 — 포트 8000의 이전 세션 백엔드 프로세스

  규칙 K-3에 따라 사용자에게 별도 보고·정리 확인 필요(unit-36-note.md §4).
