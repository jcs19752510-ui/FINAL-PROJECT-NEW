# 테스트 결과서 (Test Result Report)

## 1. 개요
- 테스트 대상: `backend/app/api/v1/ws.py`(WebSocket 인증), `backend/app/api/v1/interviews.py`(턴 제출, 텍스트/음성 공통) — 백엔드 전체 응답 불능(행) 장애의 근본 원인 수정
- 테스트 유형: 단위+통합 병합(장애 수정 1건)
- 적용 Tier: Standard (실서비스 완전 마비를 유발한 장애)
- 적용 속도 트랙: N/A
- 테스트 목적: 반복 재발한 "백엔드가 살아는 있으나 어떤 요청에도 응답하지 않는" 장애의 진짜 원인을 규명하고, 수정이 이전보다 더 강한 부하에서도 재발하지 않음을 검증. 아울러 이번 수정이 리포트 생성/열람 기능을 손상시키지 않았음을 실제 데이터로 재검증.
- 관련 산출물: 이전 결과서 `docs/harness/units/bugfix-20260922-ws-fallback-test.md`(이 결과서가 다루는 장애가 그 결과서 작성 직후 재발함에 따른 후속 조사)
- 테스트 수행자(에이전트): Claude
- 테스트 일시: 2026-09-22

## 2. 테스트 범위 및 제외 범위
- 범위(In-Scope):
  - 응답 불능 장애의 실제 근본 원인 규명(1차 조치였던 "DB 커넥션 풀 확대"가 재발로 오진임이 확인됨에 따른 재조사)
  - `ws.py::interview_ws`, `interviews.py::submit_turn`/`_submit_voice_turn`의 이벤트 루프 차단 수정
  - 수정 후 이전 장애 재현 조건보다 강한 동시 부하에서 무응답이 재발하지 않는지 검증
  - 이번 수정이 리포트 생성/조회(지원자·채용담당자 양쪽) 기능에 회귀를 유발하지 않았는지 실제 데이터로 재검증(사용자가 관리자 화면에서 리포트가 "안 보인다"고 보고한 것을 계기로)
- 제외 범위 및 사유:
  - 백엔드 전체 코드베이스의 sync-DB-in-async 패턴 전수 재작성: 이번 조사에서 위 두 파일 외에는 `async def` 라우트 핸들러 자체가 없음을 확인했으므로(3절 근거) 범위 밖. 다른 파일의 라우트는 전부 동기(`def`) 핸들러라 FastAPI/Starlette가 자동으로 스레드풀에 위임하므로 안전함.

## 3. 테스트 환경
- 실행 환경: 로컬 Windows, FastAPI 백엔드(uvicorn, `--reload` 미사용, 포트 8010), PostgreSQL 16(Docker), Redis(Docker), Celery 워커, llama-server — 전부 실프로세스
- 진단 도구: `netstat`, PowerShell `Get-Process`(CPU 델타 측정), 커스텀 asyncio 부하 스크립트(httpx+websockets, 스크래치패드)
- 전제 조건: 없음(실서비스와 동일 구성)

## 8. 리스크 및 잔존 이슈
- 이번 수정으로 백엔드의 유일한 두 `async def` 라우트 경로의 이벤트 루프 차단은 해소됐으나, **근본적으로 이 프로젝트는 동기 SQLAlchemy 세션을 async 코드 경계에서 다루는 구조**라 향후 새 기능이 `async def` 라우트를 추가하면서 동일 패턴(스레드풀 위임 누락)을 반복할 위험은 구조적으로 남아있음 — 코드 리뷰 체크리스트化를 권장(범위 밖, 인수인계)
- `tests/support/cleanup.py --all` 옵션이 Windows 콘솔(cp949)에서 이모지/특수문자 포함 경고 메시지 출력 시 `UnicodeEncodeError`로 크래시하는 기존 결함을 이번 조사 중 발견(이번 수정 범위 밖, 별도 이슈로 기록)
