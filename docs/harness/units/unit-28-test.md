# 테스트 결과서 (Test Result Report) — unit-28

## 1. 개요
- 테스트 대상: WebRTC 시그널링 서버(`app/api/v1/webrtc_signaling.py`) — SDP/ICE
  중계 메커니즘 (미디어 서버는 범위 밖, unit-28-note.md §1/§4 참고)
- 테스트 유형: 단위+통합 병합(Low 등급)
- 적용 Tier: Low(신규 격리 경로, 기존 WS 채널 무변경)
- 적용 속도 트랙: L1(경량판), 표준 수준으로 채움
- 테스트 목적: (1) 시그널링 릴레이가 실제 2개 WebSocket 피어 사이에서 동작하는지,
  (2) 인증/용량제한 등 경계 조건, (3) 기존 turn_result 채널에 회귀가 없는지
- 관련 산출물: `unit-28-note.md`, 원 계획서 §2.2/§4.1
- 테스트 수행자(에이전트): 본 세션(05+06 역할 겸임)
- 테스트 일시: 2026-09-22

## 2. 테스트 범위 및 제외 범위
- 범위: 실제 WebSocket 2피어 간 메시지 중계, 화이트리스트, 방 용량 제한, 인증
  거부, 기존 WS 채널 회귀
- 제외 범위 및 사유: 실제 미디어(오디오/비디오 RTP) 협상/전송 — 미디어 서버
  자체가 이번 유닛 범위 밖(unit-28-note.md §1), 브라우저 자동화 도구 부재로
  실제 WebRTC PeerConnection 협상도 검증 불가.

## 3. 테스트 환경
- Windows, Python 3.13(backend/.venv, `websockets` 17.1 기 설치), PostgreSQL
  (5544), 신규 uvicorn 프로세스(포트 8306), 실제 WebSocket 클라이언트 2~3개
  (Python `websockets` 라이브러리로 직접 연결)

## 8. 리스크 및 잔존 이슈
- **이 유닛만으로는 "면접관이 실제로 영상을 본다"는 원안의 목적이 달성되지
  않는다** — 미디어 서버·프론트엔드·STUN/TURN이 모두 후속 작업으로 남아있다
  (unit-28-note.md §4). ③ 매트릭스 반영 시 "완료"가 아닌 "부분 착수"로 표시.

  실제 프론트가 없어 UX 설계는 범위 밖).
- 시그널링 메시지 자체는 서버가 내용을 검증하지 않는 불투명 릴레이라, 악의적
  피어가 잘못된 SDP를 보내는 것 자체는 막지 않는다(원 설계상 시그널링 서버의
  일반적 책임 범위 밖 — 미디어 협상 단계에서 클라이언트가 걸러냄).
