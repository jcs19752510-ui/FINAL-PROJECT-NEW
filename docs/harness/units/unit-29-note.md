# unit-29 구현 노트 — 코드 실행 샌드박스 (미검증 — 중요)

- 작성 에이전트: 본 세션(05 역할), 작성일: 2026-09-22
- 원 계획서 REQ-F-004(코드 실행) / traceability REQ-022(Out-of-Scope, DEC-008)

## ⚠️ 매우 중요: 이 유닛은 "완료"가 아니라 "미검증 코드 작성"이다

`app/services/code_sandbox.py`를 실제로 Docker로 실행해 검증하려는 시도가
**Claude Code 플랫폼 자체의 안전 분류기에 의해 차단됐다**("Create RCE Surface"
사유). 이는 이 세션이 임의로 우회해서는 안 되는 플랫폼 수준의 안전장치다.

결과적으로 다음 중 **단 하나도 실측 확인되지 않았다**:
- 정상 코드(Python/JS)가 실제로 실행되고 출력을 정확히 반환하는지
- 네트워크 차단(`--network none`)이 실제로 적용되는지
- 읽기전용 파일시스템이 실제로 컨테이너 탈출/영구 변경을 막는지
- 메모리/CPU/프로세스 수 제한이 실제로 작동하는지(fork bomb 등 실제 공격
  시나리오로 검증 안 됨)
- 타임아웃 후 강제 종료(`docker kill`)가 실제로 동작하는지
- 좀비 컨테이너가 남지 않는지

**이 상태에서 이 모듈을 프로덕션에 연결하는 것은 절대 안 된다.** 코드는
설계 원칙(모듈 docstring 9개 항목)에 따라 신중하게 작성됐지만, 코드 리뷰만으로
보안 격리를 "확인됐다"고 주장할 수 없다 — 이 세션 전체가 유지해온 "실제로
실행해서 검증한 것만 완료로 표시" 원칙에 정면으로 위배되므로, ③ 매트릭스에
"완료"로 표시하지 않는다.

## 다음 단계 (사용자 결정 필요)

1. 이 세션에서 코드 실행 테스트에 대한 명시적 권한을 부여받아 직접 검증하거나,
2. 사용자가 직접 로컬에서 `execute_code_sandboxed()`를 실행해 위 6개 항목을
   확인하거나,
3. 별도의 보안 검토 전담(09단계, `09-security-auditor`)에게 넘겨 침투테스트
   수준으로 검증받아야 한다.

## 구현 범위(작성됐으나 미검증)

- `backend/app/services/code_sandbox.py`: Docker 서브프로세스 기반 격리 실행.
  Python/JavaScript 2개 언어만 구현(나머지 9개 언어는 언어별 이미지/컴파일
  스크립트 추가 필요, 범위 밖).
- `code_submissions.py`/API 엔드포인트에 연결하지 않았다 — 미검증 상태로
  실제 서비스 경로에 노출하는 것 자체가 위험하다고 판단.
