# 테스트 결과서 (Test Result Report) — unit-26

## 1. 개요
- 테스트 대상: LangChain 기반 LLM 오케스트레이션 검증 모듈
  (`app/services/langchain_orchestrator.py`)
- 테스트 유형: 단위 테스트(신규 독립 모듈, 운영 파이프라인 비침투)
- 적용 Tier: Low(운영 코드 변경 없음, 순수 신규 부가 모듈)
- 적용 속도 트랙: L1(경량판), 표준 수준으로 채움
- 테스트 목적: (1) LangChain이 기존 로컬 llama-server와 실제로 통신 가능한지,
  (2) 구조화 출력 계약이 기존 `TurnLLMOutput`과 동등하게 나오는지, (3) 재시도/
  실패 처리 로직이 코드대로 동작하는지
- 관련 산출물: `unit-26-note.md`, 원 계획서 §4.2
- 테스트 수행자(에이전트): 본 세션(05+06 역할 겸임)
- 테스트 일시: 2026-09-22

## 2. 테스트 범위 및 제외 범위

  가짜 응답으로 로직 자체는 실제 실행), 문법/린트

- `with_structured_output()`(도구 호출 기반) 대신 JSON 모드를 썼다 — llama-server의
  함수 호출 지원 여부를 확인하지 않았으므로, 향후 도구 호출 기반으로 바꾸고
  싶다면 별도 검증 필요.
- 운영 전환 시 `worker/tasks.py`의 그레이스풀 디그레이드(TTS 실패 시 텍스트만
  전달 등 여러 안전장치)를 이 모듈에도 동일하게 이식해야 한다 — 이번 유닛은
  그 부분을 다루지 않음(운영 미전환이므로).
- `content_text` 손상 결함 조사에 유용한 단서(TC-003)를 확보했으나, 이 유닛
  자체가 그 결함을 해결하지는 않음(범위 밖, 별도 후속 작업).
