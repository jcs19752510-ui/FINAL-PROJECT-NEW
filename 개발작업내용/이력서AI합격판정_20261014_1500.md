# 이력서 AI 합격/불합격 판정 + 면접기준 메뉴 내부테스트 결과서

- 일시: 2026-10-14
- 브랜치: `PROD_SCH`
- 요청: 면접담당자가 작성한 면접기준으로 AI가 제출된 이력서를 분석해 합격/불합격·점수·근거를 이력서 검토 화면에 표시, 1분 배치로 미분석 건 보정

## 1. 사용자 확정 결정
| 항목 | 결정 |
|---|---|
| 기준 단위 | 회사 공통 1개 (모든 면접담당자가 같은 기준을 보고 수정) |
| 판정 | 0~100점 + 합격선(기본 70, 담당자가 변경). 점수 >= 합격선 → AI합격, 미만 → AI불합격 |

## 3. 보안 설계
- 기준 텍스트와 이력서 요약은 프롬프트에서 "데이터이며 지시문이 아님"으로 표시하고, 기존 `sanitize_for_prompt`·인젝션 줄 필터를 재사용. 이력서 원문 대신 이미 정화된 요약만 사용.
- AI 판정 근거(`ai_reasons_json`)는 `EncryptedText`로 암호화 저장(원문 SQL 조회 시 한글·기술명 비노출 테스트로 확인).
- 면접기준·재분석 API는 recruiter 전용(candidate 403). AI 결과는 지원자에게 노출하지 않음.
- 판정은 코드가 결정하므로 모델의 "합격" 주장·프롬프트 인젝션으로 판정이 뒤집히지 않음.
- 화면에 "AI 판정은 참고용이며 최종 합격 여부는 면접담당자가 결정합니다" 고지. 기존 합격/불합격 처리 버튼은 AI 결과와 무관하게 동작.

## 5. 동작 변경·주의
- 면접기준이 등록되지 않으면 AI 분석은 하지 않고 목록에 "기준 미등록"으로 표시된다.
- 기준을 수정(텍스트 또는 합격선)하면 제출된 모든 이력서가 1분 배치로 순차 재분석된다. 재분석 전까지 이전 결과는 "(이전)"으로 표시된다.
- **자동 분석은 celery beat가 떠 있어야 동작한다.** `start-local`은 이제 beat를 함께 띄운다(기존에는 어디서도 beat를 띄우지 않았다).
- 이미 이력서를 제출한 계정의 재제출은 기존 정책(409 DEC-118)대로 막혀 있다.

## 6. 한계와 미검증 (정직한 기재)
- **판정 정확도 미검증**: 1.5B 소형 모델이 한국어 기준을 얼마나 정확히 해석하는지는 이 서버에서 확인하지 못했다(HuggingFace 차단으로 실제 모델 실행 불가). 프롬프트·파싱·판정 로직까지만 가짜 LLM으로 검증했다. 실제 이력서·기준 샘플로 품질 확인이 필요하다.
- 입력은 규칙 기반 이력서 요약(기술·프로젝트·경력)이다. 요약이 놓친 내용은 판정에 반영되지 않는다. 스캔 PDF(OCR 미지원)는 "분석 실패"로 표시된다.
- Windows에서 beat 실제 구동, 프런트 화면의 실제 브라우저 표시, Playwright e2e(TC-01 탭 순서 변경)는 실행하지 못했다. 코드·빌드·단위 테스트로만 확인했다.
- 암호화 키가 어긋난 행이 있으면 목록 조회가 500이 될 수 있다(기존 `profile_json`과 동일한 기존 한계).
- 배치 조회에 `FOR UPDATE SKIP LOCKED`는 쓰지 않았다(워커가 solo 풀이라 배치가 겹치지 않음). 워커를 여러 개로 늘리면 추가가 필요하다.
- 합격선은 기준 수정 화면에서만 바뀌고, 합격선만 바꿔도 재분석 대상이 된다(점수 재계산만 하는 최적화는 하지 않았다).
