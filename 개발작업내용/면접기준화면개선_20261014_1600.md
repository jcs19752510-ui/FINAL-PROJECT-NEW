# 면접기준 화면 개선(입력창 상시 표시 + 기본 예시) 내부테스트 결과서

- 일시: 2026-10-14 / 브랜치: `PROD_SCH`
- 요청 배경: 로컬 PC에서 `/recruiter/criteria`가 "Not Found"만 보이고 입력창이 없었다.

## 1. 원인
- 코드 문제가 아니라 **PC의 백엔드(8001)가 `git pull` 이전 코드로 떠 있어** `GET /api/v1/recruiter/screening-criteria`가 404였다(서버 쪽 라우트 등록·테스트 17건은 정상).
- 화면은 불러오기에 실패하면 입력창을 숨기고 오류만 보여 주는 구조였다.

## 2. 변경 내용
| 구분 | 내용 | 파일 |
|---|---|---|
| 입력창 상시 표시 | 불러오기 실패해도 TEXTAREA(22행, 4000자 제한·글자수 표시)와 합격선 입력을 항상 표시. 저장은 서버 연결 후에만 가능(버튼 비활성) | `frontend/app/recruiter/criteria/page.tsx` |
| 오류 안내 | 404 → "백엔드를 재시작(start-local.ps1)한 뒤 다시 불러오기", 네트워크 오류 → "백엔드(8001) 확인", 403 → 권한 안내. "다시 불러오기" 버튼 | 〃, `lib/screeningView.mjs` |
| 기본 예시 | 기준이 한 번도 등록되지 않았으면 **AI·IT 개발자 경력 5년 이상, 2026년 10월 기준, 바이브코딩 가능자 포함** 예시(1,331자)를 초안으로 채움. 6개 평가항목(경력20·핵심역량25·AI25·바이브코딩15·인프라협업10·성장5=100점), 필수 조건, 감점 요인 포함. **"등록"을 눌러야 저장**되고 그때부터 AI 분석 시작 | 〃 |
| 예시 다시 불러오기 | "기본 예시 불러오기" 버튼(입력 내용이 있으면 덮어쓰기 확인창) | 〃 |
