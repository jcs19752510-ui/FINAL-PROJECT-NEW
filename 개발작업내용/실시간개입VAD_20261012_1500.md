## 2. 설계상 보안·안전 결정
- 판정과 재검증은 서버가 한다. 클라이언트가 `interrupt_reason`을 위조해도 짧은 답변(실제 길이 < 임계치의 90%)이나 주제에 맞는 답이면 무시된다.
- 서버는 상태를 저장하지 않는다. 연속 하락 횟수는 클라이언트가 되돌려 보내며(0~10으로 제한), 최종 제출은 단독 재검증한다.
- 입력 방어: 경과 시간(NaN·무한·음수·문자열 → 0, 상한 3600초), `answer_so_far` 4000자 절단.
- 임베딩 실패 시 개입하지 않는다(안전한 쪽으로 실패).
- 개입 문구는 모델이 아니라 서버 고정 문구다(1.5B 모델 말투에 의존하지 않음).

## 4. 한계와 미검증 (정직한 기재)
- 개입 지연은 미리보기 주기 4초 + STT·임베딩 처리로 약 5~10초다. 서브초 끼어들기가 아니다. 스트리밍 STT·GPU 서버가 필요하며 별도 과제다.
- 주제 이탈 판정은 임베딩 유사도 근사치다. 임계치 0.15는 기본값이며 실제 면접 데이터로 보정이 필요하다.
- 이 서버는 HuggingFace가 막혀 있어 실제 한국어 STT·임베딩 모델로 검증하지 못했다. 로직은 가짜 임베더와 합성 오디오로 검증했다.
- 에너지 VAD는 소음 환경에서 오탐할 수 있다(소음 바닥 적응으로 완화). 바지인은 에코 취소·헤드셋을 전제한다. 실제 마이크·스피커 에코 환경은 미검증이다.
- 실제 면접 화면(`page.tsx`)은 로그인·백엔드·WebSocket 때문에 구동하지 못했다. E2E는 같은 lib를 쓰는 임시 화면이며, `page.tsx` 배선은 tsc·eslint·build로만 확인했다. 프런트-백엔드 실제 연동 시험은 남아 있다.
- 바지인은 발화 확정(약 300ms) 후 녹음을 시작해 첫 말머리가 잘릴 수 있다(pre-roll 버퍼 미구현). 재생 중 마이크가 열려 브라우저 녹음 표시가 뜬다.
- Silero VAD로 교체할 수 있도록 DSP 코어를 분리했다.
